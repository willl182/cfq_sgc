# Problem Record (Troubleshooting)

**Severity**: High

## The Problem

Tras desplegar la app completa a produccion, el usuario reporto que al recargar "perdio" cambios en la base de datos.

## Diagnosis

La app local/dev habia estado usando Convex dev (`valiant-stingray-191`), mientras que el despliegue correcto de produccion usa Convex prod (`sensible-goose-293`).

Conteos leidos con `npx convex data`:

- Dev: `catalogItems` 304, `productLists` 8, `productListSnapshots` 10, `catalogChangeHistory` 99.
- Prod: `catalogItems` 296, `productLists` 0, `productListSnapshots` 0, `catalogChangeHistory` 0.

Esto indica diferencia de deployment, no borrado confirmado de datos.

## User-Requested Corrections

- El usuario confirmo luego: "listo ya quedo".
- No se ejecuto migracion/importacion de datos.

## The Solution / Workaround

Se detuvo la migracion dev -> prod que se estaba preparando para evitar tocar datos sin necesidad.

## Learnings to Preserve

- Antes de desplegar frontend contra Convex prod, confirmar donde estan los datos que el usuario considera canonicos.
- Si hay que mover datos dev -> prod, hacer primero export de ambos deployments.
- No usar `npx convex import --prod --replace` ni `--replace-all` sin confirmacion explicita.
