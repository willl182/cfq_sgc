# Problem Record (Troubleshooting)

**Severity**: High

## The Problem

El usuario reporto nuevamente que al recargar desaparecian cambios de base de datos.

## Diagnosis

Se confirmo la misma divergencia de deployments:

- Convex dev `valiant-stingray-191` tenia:
  - `catalogItems` 304
  - `productLists` 8
  - `productListSnapshots` 10
  - `catalogChangeHistory` 99
- Convex prod `sensible-goose-293` tenia:
  - `catalogItems` 296
  - `productLists` 0
  - `productListSnapshots` 0
  - `catalogChangeHistory` 0

La app publica estaba correctamente apuntando a prod, por eso no mostraba los datos existentes en dev.

## The Solution / Workaround

Antes de tocar prod se crearon respaldos:

- `web/backups/convex/dev_20260615_113015.zip`
- `web/backups/convex/prod_20260615_113015.zip`

Luego se importo dev sobre prod:

```bash
npx convex import --prod --replace --yes web/backups/convex/dev_20260615_113015.zip
```

Resultado verificado en prod:

- `catalogItems` 304
- `productLists` 8
- `productListSnapshots` 10
- `catalogChangeHistory` 99

## Learnings to Preserve

- La URL publica debe apuntar a Convex prod, pero el equipo debe saber que cambios hechos contra dev no apareceran ahi.
- Antes de cualquier importacion prod, exportar dev y prod.
- Agregar indicador visual del deployment actual ayudaria a evitar que usuarios editen en una base y miren otra.
