# Problem Record (Troubleshooting)

**Severity**: Medium

## The Problem

Al abrir una lista guardada y editar sus componentes, el estado visible en la vista de snapshots/listas quedaba con el valor inicial (`CUMPLE`, `NO_CUMPLE`, etc.). El usuario terminaba creando listas duplicadas porque el autoguardado no reflejaba el nuevo cumplimiento.

## User-Requested Corrections

- Corregir que al editar una lista el autoguardado actualice el estado visible de cumplimiento.
- Evitar que el usuario tenga que duplicar listas para ver el nuevo estado.

## The Solution / Workaround

- Se agrego `productLists.updateLiveList` en Convex para persistir cambios de una lista viva existente sin crear snapshots nuevos.
- Se agrego autoguardado debounced en `web/src/main.tsx` cuando hay `editingListId`.
- La fila visible de snapshots/listas recalcula el resumen desde la lista viva actual si existe; el snapshot congelado queda como fallback historico.

## Learnings to Preserve

- `saveWithSnapshot` debe reservarse para crear versiones congeladas historicas.
- Las vistas operativas de listas editables deben derivar estado desde la lista viva actual, no desde el primer snapshot congelado.
- Si se mantiene una pantalla llamada snapshots pero se usa como selector de listas editables, debe distinguir claramente estado actual vs version historica.
