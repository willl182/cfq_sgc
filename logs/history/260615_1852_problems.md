# Problem Record (Troubleshooting)

**Severity**: Medium

## The Problem

El usuario no podia crear una materia prima nueva desde la UI aunque estuviera en rol admin.

## Diagnosis

- La mutacion Convex `catalog:createManual` permite crear items cuando `actor.role` es `admin`.
- Una prueba directa contra Convex con `MP9999` funciono, por lo que el bloqueo no era el permiso admin.
- La UI consultaba `api.catalog.list` sin `includeArchived`, por lo que solo recibia activos.
- `nextCatalogInternalId()` calculaba el siguiente ID con esa lista incompleta. Si existia un item archivado con ese ID, Convex rechazaba la creacion porque `internalId` debe ser unico.

## The Solution / Workaround

Se cambio `web/src/main.tsx` para cargar el catalogo remoto con archivados incluidos:

```ts
const remoteCatalog = useQuery(api.catalog.list, { includeArchived: true }) as ConvexCatalogItem[] | undefined
```

La UI ya filtra activos con `activeCatalog`, por lo que los archivados no se muestran, pero si participan en el calculo del siguiente ID.

## Validation

- `pnpm test`: 17 tests pasaron.
- `pnpm build`: paso.
- Deploy a produccion completado con alias `https://formulador-sub.vercel.app`.

## Learnings to Preserve

- Para generar IDs secuenciales de catalogo, siempre considerar registros archivados porque Convex conserva unicidad por `internalId`.
- No asumir que un fallo de creacion en admin es de permisos; revisar primero unicidad, archivados invisibles y validadores de Convex.
