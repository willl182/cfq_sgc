# Problem Record (Troubleshooting)

**Severity**: Medium

## The Problem

El ajuste anterior hizo que `remoteCatalog` consultara Convex con `{ includeArchived: true }` para evitar reutilizar IDs internos archivados al crear una materia prima nueva. El usuario reporto que "la tabla tiene error" despues del despliegue.

## User-Requested Corrections

- "no del todo"
- "la tabla tiene error"

## The Solution / Workaround

Se desacoplaron dos usos del catalogo en `web/src/main.tsx`:

- `remoteCatalog = useQuery(api.catalog.list, {})`: fuente normal para renderizado de tabla, selectores, calculos y exportaciones activas.
- `remoteCatalogWithArchived = useQuery(api.catalog.list, { includeArchived: true })`: fuente completa usada para calcular el siguiente `internalId` y evitar colisiones con archivados.

Tambien se ajusto el modo local para que creacion y archivado preserven registros archivados usando `catalogWithArchived`.

## Learnings to Preserve

- No usar una unica coleccion con archivados como fuente global de UI si la mayoria de vistas esperan solo activos.
- Para IDs monotonicamente crecientes, calcular contra todos los registros, pero renderizar contra activos.
- Validar siempre con `pnpm test`, `pnpm build` y desplegar a produccion en cambios de `formulador-sub_1/web`.
