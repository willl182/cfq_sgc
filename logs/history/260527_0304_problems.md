# Problem Record (Troubleshooting)

**Severity**: High

## The Problem

The Apps Script Web App returned:

- `Cannot read properties of null (reading 'getSheetByName')`

This happened because the backend script was not bound to an active spreadsheet and used `SpreadsheetApp.getActiveSpreadsheet()`.

Later, manual CSV import also failed from the frontend, indicating that `POST` handling between browser and Apps Script needed a more tolerant transport path.

## User-Requested Corrections

- Keep the UI simple.
- Keep Google Sheets as the backend.
- Hide the backend URL from the user.
- Make the app work "ya".
- Preload the catalog automatically.

## The Solution / Workaround

1. Switched the backend to open the target spreadsheet explicitly by ID:
   - `SpreadsheetApp.openById(SPREADSHEET_ID)`
2. Redeployed the Web App as a new version.
3. Verified `action=ping` on the `/exec` URL returned `{"status":"ok"}`.
4. Added a precache path for the bundled CSV when the sheet is empty.
5. Updated the client `POST` path to try standard `fetch` first and fall back to hidden form submission.

## Learnings to Preserve

- A standalone Apps Script project must not rely on `getActiveSpreadsheet()` unless it is bound to the spreadsheet container.
- Saving code in Apps Script is not enough; the Web App deployment must be updated to a new version.
- For browser-to-Apps Script persistence, keep a fallback transport available because `POST` responses can be finicky depending on deployment and cross-origin behavior.
- When the catalog sheet is empty, a bundled CSV can be used to bootstrap the backend and reduce manual setup.
